# 新手引导（30 秒上手）

装好之后不用先读 40 份角色提示词，也不用背命令。说人话就行。

## 第一步：说一句话

任选一种：

- **小活**：“用代码工坊专家团，把登录页的报错修一下。”
- **完整功能**：“用代码工坊专家团，给现有后台加一个订单导出，走完整流程。”
- **全量**：“用代码工坊专家团，全量启用，从 0 做一个会员小程序，四组都要有产出。”

主理人会自动判档，先说一行编队，再开工：

```text
【编队】标准档 · 11 人 · 3 波 · 判档 8/18（多模块 + 集成验证）
【波次】plan: 产品组 4 人 → build: 工程组 5 人 → gate: 质量组 2 人
【升级】发现 ≥3 组并行或生产风险会自动升档；要立刻全量说“全量启用”
```

## 第二步：看三个东西

1. **任务卡**：目标、输入、约束、交付物、证据、验收、风险、截止。
2. **波次**：谁先上、谁后上、依赖是什么。
3. **交付包**：产物路径 + 证据 + 遗留风险，没有证据的“完成”会被打回。

## 第三步：随时改编队

| 你说 | 发生什么 |
|---|---|
| “全量启用” / “40 人全开” | 40 人全部进计划，分波次推进 |
| “强制全量” | 任务再小也全开，只提醒一次成本 |
| “标准档” / “多组协同” | 6~10 人 |
| “精简档” / “最小团队” | 2~4 人，适合单点任务 |
| “加工程组” / “只要审查” | 按指令重排，不重新论证 |
| “打回，补测试证据” | 回到上一阶段，写明缺什么、补什么 |
| “停” | 停止派新活，保留已完成交付包 |

## 第一次用建议先自检

说：

> **“用代码工坊专家团做个自检：报编制、档位、下一步。”**

预期它会给出：40 人组织与四个组长、当前判档逻辑、以及一句“给我一个真实任务即可开工”。这能确认 Skill / 专家团已被正确加载。

## 常见误解

- **“装上了就应该 40 人一起动”**：不会。默认按任务判档，避免为一个小修拉开 40 人。想全量，明说。
- **“全量就是 40 个线程”**：不是。40 人进计划、分波次，并发仍受平台限制。
- **“它会自己猜验收标准”**：不会。验收不清时它会先补任务卡，不靠猜开工。
- **“没有证据也算完成”**：不算。交付必须带命令、日志、测试、截图或接口返回。

## 它适合什么、不适合什么

适合：从需求到上线的软件交付、代码审查与漏洞排查、网站搭建、动效与可视化、产品规划与 PRD。

不适合：纯聊天、一次性文案、与代码无关的行政事务。这些直接说就行，不必拉起团队。
