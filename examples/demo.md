# 一次完整交付（示意）

> 这是为了说明流程而编写的示例，不是某个真实项目的运行记录。真实交付里的证据应替换成你自己的命令输出、测试报告和截图。

## 用户

> 用代码工坊专家团，给现有后台加一个订单导出，走完整流程。技术栈是 Next.js + Postgres，不要动现有登录逻辑。

## 主理人（codeforge-team-lead）

```text
【编队】标准档 · 11 人 · 3 波 · 判档 9/18（多模块 + 数据导出 + 权限约束）
【波次】plan: 产品组 3 人 → build: 工程组 4 人 → gate: 质量组 2 人 → deliver: 文档 1 人
【升级】发现需改数据库结构或涉及生产发布时升档并广播
```

任务卡 T-001 已建立：

```yaml
objective: 管理员可按时间范围导出订单 CSV，导出结果与列表筛选一致
constraints: 不改登录与权限中间件；导出单次上限 5 万行；不新增第三方依赖
deliverable: 可运行代码 + 迁移脚本（如需）+ 使用说明
evidence: 单元测试、接口返回样例、5 万行压测结果、权限回归用例
acceptance: 见下
```

## 产品规划组

- 需求分析师补验收口径：字段顺序、时区、金额精度、空结果行为、越权访问必须 403。
- 产品经理定范围：本期只做 CSV，不做异步任务与邮件通知。
- 交互设计师给出入口位置、加载态、失败重试与文案。

**交付**：PRD 一页、验收清单 8 条、交互说明 1 份。

## 工程实现组

- 架构师确认走流式查询，避免一次性加载 5 万行。
- 后端工程师实现导出接口与游标分页，复用现有权限校验。
- 前端工程师加入口与下载反馈，处理空结果与超时。
- 数据库工程师确认现有索引可支撑时间范围查询，无需迁移。

**交付**：代码 PR、接口样例、5 万行压测记录（耗时与内存峰值）。

## 质量安全组

- 代码审查：发现导出未限制列，存在越权读取内部字段的风险 → 打回。
- 补上字段白名单后复审通过。
- 测试工程师覆盖：正常导出、空结果、超范围、无权限、并发导出。
- 安全审计确认：不存在 SQL 注入与越权；导出文件名做了转义。

**门禁结论**：有条件通过——需补一条「并发导出」的自动化用例。

## 体验交付组

技术文档工程师补 README：入口位置、字段说明、上限与失败处理。

## 主理人终验

```yaml
status: done
acceptance: 8/8 通过（并发用例已补）
evidence: PR 链接、测试报告、压测记录、权限回归截图
risks: 超过 5 万行需走异步方案，留到下一期
next: 观察一周导出失败率，再决定是否做异步任务
```

## 这个例子里值得注意的三件事

1. **打回是正常的。** 代码审查打回了一次，原因和补什么写得很具体，所以只返工了一轮。
2. **证据是可检查的。** 压测给了数字，权限给了回归用例，而不是「已验证」三个字。
3. **范围被守住了。** 异步导出被明确推到下一期，没有在交付前悄悄扩张。
